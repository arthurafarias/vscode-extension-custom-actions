# SRS-003: Create New Action

Extends the extension described in [SRS-001](SRS-001.md) and complements [SRS-002](SRS-002.md). Today an
action can only be added by hand: create a folder under `.vscode/custom-actions/` (or another configured
directory), write a `meta.json`, write an `entry.js`. This scaffolds that structure from inside VS Code
and lands the user in the new `entry.js` ready to write the action's logic.

## Requirement 01 — Command registration

Add a new command, `customActions.new`, contributed statically in `package.json` (title:
`Custom Actions: Create New Action...`), registered and disposed the same way as the existing
`customActions.run` and `customActions.reload` commands.

## Requirement 02 — Choosing the target directory

Read the configured directories (`customActions.directories`, default `.vscode/custom-actions`).

- If exactly one directory is configured, use it directly.
- If more than one is configured, show a Quick Pick of the configured directories so the user chooses
  where the new action is created.

## Requirement 03 — Naming the action

Prompt for an action name via an input box. The name becomes the folder name and must be validated
before accepting it:

- non-empty,
- restricted to filesystem-safe characters (letters, digits, hyphens, underscores),
- must not already exist as a subfolder of the chosen target directory (actions must be unique per
  Requirement 03/04 of SRS-001 — duplicate names across directories are already treated as load
  failures).

## Requirement 04 — Describing the action

Prompt for a required, non-empty description. This is the same required field `readMeta` already
enforces in `meta.json`, and it is what shows up as the entry's description in the `Custom Actions:
Run...` and `Custom Actions: Edit...` pickers.

## Requirement 05 — Scaffolding files on disk

Create `<targetDir>/<actionName>/` and write:

- `meta.json`, containing at least `name` and `description` as entered above, matching the shape
  documented in the README (`name`, `description`, optional `category`).
- `entry.js`, a stub that already exports a valid function in one of the three accepted forms
  (`module.exports = fn`), matching the `({ vscode, workspaceRoot, actionDir, output })` signature the
  extension invokes actions with, so the freshly created action loads successfully on the very next
  reload instead of surfacing as a load failure.

## Requirement 06 — Jump to source and open entry.js

After scaffolding:

1. Reveal the new action's folder / `entry.js` in the Explorer tree (jump to source folder).
2. Open `entry.js` in an editor tab, focused, ready to edit.

## Requirement 07 — Registration is automatic

Do not manually invoke a reload. The file watcher already set up per configured directory observes the
new folder's creation and triggers the existing debounced `loadActions` reload, so the new action
registers itself as `customActions.<actionName>` the same way any hand-created action does.

## Requirement 08 — Preconditions

Requires an open workspace folder (same precondition `loadActions` already checks); if none is open, show
an error message and abort before prompting for a name or description.
