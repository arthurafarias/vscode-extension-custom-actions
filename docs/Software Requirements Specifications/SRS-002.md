# SRS-002: Edit Existing Action

Extends the extension described in [SRS-001](SRS-001.md). Today a user can discover and *run* a loaded
action (`Custom Actions: Run...`) but has no built-in way to jump to its source. Editing means opening
the action's `entry.js` in the editor, without hunting for it manually in the Explorer.

## Requirement 01 — Command registration

Add a new command, `customActions.edit`, contributed statically in `package.json` (title:
`Custom Actions: Edit...`), registered and disposed the same way as the existing `customActions.run`
and `customActions.reload` commands (pushed onto `context.subscriptions`).

## Requirement 02 — Action picker

Invoking the command shows a Quick Pick populated from the same in-memory registry the `run` command
already uses (the map of loaded actions built by `loadActions`), listing each action's display label and
description. It must reflect only currently *successfully loaded* actions — one whose `meta.json`/`entry.js`
failed to load should not appear, consistent with how `Custom Actions: Run...` behaves today.

If zero actions are loaded, show the same empty-state message pattern as `customActions.run`
("No custom actions loaded...") instead of opening an empty picker.

## Requirement 03 — Resolving the source location

Each entry in the registry must carry (or make resolvable) the absolute path to its own action directory,
so that picking an entry yields `<actionDir>/entry.js` without re-deriving it from the configured
`customActions.directories` list. This works no matter which configured directory (default
`.vscode/custom-actions`, or any additional entry from the `customActions.directories` setting) the
action actually lives in.

## Requirement 04 — Jump to source and open entry.js

On selection:

1. Reveal `entry.js` in the Explorer tree (jump to source folder).
2. Open `entry.js` in an editor tab, focused, ready to type.

No workspace-trust check is required for this command — unlike `customActions.run`, it only opens and
reveals a file; it never invokes the action's exported function.

## Requirement 05 — No side effects on the registry

Editing must not trigger a manual reload by itself. The existing file watcher (already wired up per
configured directory) picks up any subsequent save to `entry.js` and hot-reloads it, exactly as it does
today for direct edits made outside this command.
